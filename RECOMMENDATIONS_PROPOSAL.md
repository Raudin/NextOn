# Nexton Movie & Series Recommendation Engine Proposal

## Executive Summary

This document proposes a lightweight, easy-to-configure recommendation solution for the Nexton platform. Rather than introducing complex machine learning models or high-maintenance infrastructure, this proposal leverages Nexton's existing architecture (**Go/Gin backend**, **TMDB integration**, **SQLite user data**, and **React Native Expo mobile app**) to deliver highly accurate movie and TV series recommendations.

The proposed architecture relies on TMDB's native recommendation/similarity endpoints combined with a simple user-history aggregation algorithm on the backend, configurable entirely via environment variables.

---

## 1. System Context & Recommendation Opportunities

Nexton currently tracks user watch history, watchlist items, and favorite items in SQLite while pulling rich metadata from TMDB.

### Recommendation Use Cases:
1. **Item-Level Recommendations ("More Like This")**:
   - Displayed on the **Media Details** screen for both movies and TV shows.
   - Shows titles that viewers of the current item also watched or titles with similar themes/genres.
2. **Personalized User Recommendations ("Recommended for You")**:
   - Displayed on the **Home** tab as a curated horizontal scroll section.
   - Computed dynamically using the user's recent highly-rated or watched titles from their watchlist and watch history.
3. **Discover Screen Hybrid**:
   - Enhancement to the **Discover** tab with configurable recommendation collections (e.g. top recommendations from the user's favorite genre).

---

## 2. Proposed Recommendation Strategies (Low Complexity)

### Strategy A: TMDB Native Recommendation & Similar API (Item-Level)
TMDB provides two specialized endpoints per media type:
- `GET /3/movie/{movie_id}/recommendations` & `GET /3/tv/{tv_id}/recommendations`: Returns curated recommendations generated by TMDB's algorithm based on user voting and viewing patterns.
- `GET /3/movie/{movie_id}/similar` & `GET /3/tv/{tv_id}/similar`: Returns items that share similar keywords, genres, and attributes.

**Why this works:**
- Zero ML model maintenance required.
- Instantly available for millions of movies and series.
- Integrated into Nexton's existing `tmdbGet` caching and rate-limiting infrastructure.

### Strategy B: Watch History & Watchlist Aggregation (User-Level)
To generate personalized user recommendations without extra infrastructure:
1. Fetch the user's **5 most recently watched titles** or **5 highest-rated items** from SQLite (`watched_items` and `user_favorites`).
2. Query TMDB's `/recommendations` endpoint for each seed item in parallel (using Go goroutines).
3. Merge and deduplicate the resulting items.
4. Filter out titles that the user has **already watched** or currently has on their **watchlist**.
5. Return the top $N$ items (e.g., 10–20 items).

### Strategy C: Fallback / Mock Mode (`TMDB_API_KEY=dummy`)
When running locally or in test environments without a valid TMDB key:
- Return pre-configured mock media items filtered by shared genres.
- Seamlessly fits into Nexton's mock data structure (`getMockMediaDetails`, `getMockDiscoverData`).

## 3. Configuration & Easy Setup

The key goal is making recommendations effortless to enable, tweak, or disable across environments without code changes.

### Backend Environment Variables (`backend/.env`)

| Variable | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `RECOMMENDATIONS_ENABLED` | `bool` | `true` | Global toggle to enable/disable recommendation endpoints. |
| `RECOMMENDATION_STRATEGY` | `string` | `tmdb_mix` | Strategy selection: `tmdb_recommendations`, `tmdb_similar`, or `tmdb_mix` (blends recommendations & similar). |
| `RECOMMENDATION_LIMIT` | `int` | `15` | Maximum number of recommended items returned per request. |
| `RECOMMENDATION_CACHE_TTL` | `string` | `1h` | Cache duration for recommendation payloads (In-Memory / Redis). |
| `RECOMMENDATION_SEED_COUNT` | `int` | `5` | Number of recent watched/watchlist items used to build user recommendations. |

### Example `.env` Configuration:
```env
# Enable recommendations with default TMDB recommendation mix
RECOMMENDATIONS_ENABLED=true
RECOMMENDATION_STRATEGY=tmdb_mix
RECOMMENDATION_LIMIT=15
RECOMMENDATION_CACHE_TTL=1h
RECOMMENDATION_SEED_COUNT=5
```

## 4. Backend API Design & Architecture

### Endpoint Specifications

#### 1. Media Recommendations (`GET /api/media/:type/:id/recommendations`)
- **Access**: Public
- **Description**: Returns recommended movies or TV shows similar to the requested item.
- **Query Params**:
  - `limit` (optional): Override recommendation count (e.g. `?limit=10`).
- **Response**: Array of `TMDBMedia` items enriched with OMDb/ratings if cached.

#### 2. User Recommendations (`GET /api/recommendations/user`)
- **Access**: Private (Requires `Authorization: Bearer <token>`)
- **Description**: Returns personalized recommendations based on the caller's watch history and watchlist.
- **Response**:
```json
{
  "seed_count": 3,
  "recommendations": [
    {
      "id": 550,
      "title": "Fight Club",
      "media_type": "movie",
      "poster_path": "/pB8BM7pdSp6B6Ih7QZ4DrQ3PmJK.jpg",
      "vote_average": 8.4,
      "release_date": "1999-10-15"
    }
  ]
}
```

### Response Caching Strategy
Recommendation queries will use Nexton's existing dual-layer caching system:
1. **In-Process Cache (`tmdbResponseCache`)**: Keeps TMDB response bodies in memory for `RECOMMENDATION_CACHE_TTL`.
2. **Redis Cache (Optional)**: Shared across container instances if `REDIS_URL` is set.
3. **HTTP ETag & Conditional Requests**: Returns `304 Not Modified` for `If-None-Match` checks.

## 5. Mobile Frontend UI Integration Plan

### 1. Media Details Screen (`mobile/src/app/media/[type]/[id].tsx`)
- Add a **"More Like This"** horizontal card carousel beneath the trailer and cast sections.
- Re-use existing `MediaCard` / poster components for consistent visual styling.
- Tapping a recommended item navigates seamlessly to that item's detail view.

### 2. Home Tab Screen (`mobile/src/app/(tabs)/index.tsx`)
- Add a **"Recommended For You"** section above or below the current "Ready to Watch" schedule.
- Show an intuitive fallback ("Discover Trending Media") for new users who haven't added or watched items yet.

This recommendation strategy provides an immediate quality-of-life upgrade for Nexton users with **zero algorithmic complexity**, zero expensive infrastructure costs, and minimal configuration effort.
